# evaluation

Phase 13: the "detection-only vs. full-system" baseline comparison architecture
spec Section 19's Phase 13 gate requires ("At least the detection-only vs.
full-system baseline comparison has real, reported numbers"), implemented and
run for real. Reports land in the top-level `evaluation/` directory, not here
-- this package is the real code that produces them.

Status: Phase 13 complete.
- `baseline_systems.py`: the three systems' response-decision logic
  (`detection_only`, `fixed_response`, `full_system`), plus the
  `unsafe_autonomous_action_rate` / `unnecessary_isolation_rate` metric
  definitions. `full_system` calls the real, already-shipped
  `RuleBasedRiskModel` (Phase 5) and `PolicyEngine` (Phase 6) -- this module
  does not reimplement their rules. The still-nonexistent LLM-backed agents
  (Threat Reasoning, Healthcare Context, Response Planning -- no real LLM
  backend exists anywhere in this codebase, unchanged since Phase 4) are
  stood in for by small, named, deterministic functions, each one an honest
  restatement of a trial's real ground truth, never an arbitrary or
  hand-tuned value. See the module's own docstring for the full disclosure.
- `run_baseline_comparison.py`: trains a model fresh in-process against the
  synthetic stand-in dataset (same pattern as
  `backend/tests/test_lifecycle_integration.py` and `tests/e2e/conftest.py`
  -- never depends on a pre-existing committed artifact), pairs every row of
  its real held-out test split with an independently, randomly sampled
  device context, runs all three systems over every trial, and writes a
  real JSON + Markdown report to `evaluation/`.
- `tests/test_baseline_systems.py`: unit tests for the decision logic,
  including a confidence-sweep version of Section 17 Scenario B's central
  claim ("the full system never autonomously executes a disruptive action
  on a high-stakes real attack") checked across every confidence level that
  can fire a detection, not just one hand-picked value.

Real result from the last run (`evaluation/phase13_baseline_comparison.md`
has the full report): across 2038 held-out trials per model, 162 were both
a real attack and a HIGH-criticality, patient-dependent device --
`fixed_response` (the naive, non-patient-aware baseline) autonomously
executed a disruptive action on **100%** of those (162/162); `full_system`
did so on **0%** (0/162), routing every one of them to human approval
instead, for both Random Forest and XGBoost detectors. This is the Phase
11 E2E suite's Scenario B finding, generalized from two fixed test
scenarios to hundreds of randomized trials.

Disclosed limitation, not hidden: `unnecessary_isolation_rate` could not be
measured this run (0/0 denominator) -- both trained detectors had zero
measured false positives on their held-out split of the synthetic dataset,
whose per-class profiles are Gaussian-separated by construction and
therefore cleaner than real network traffic is likely to be. The metric
and its comparison logic are real and unit-tested; what is missing is a
dataset with enough class overlap to actually produce a false positive to
measure it against -- the real CICIoMT2024 dataset is the natural
candidate once it is downloadable (see `datasets/LICENSE_NOTES.md`).
